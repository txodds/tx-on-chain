## Activation Message

After `subscribe(serviceLevelId, durationWeeks)` confirms, activate the API token by signing this exact message with the same wallet that submitted the transaction:

```text
${txSig}:${selectedLeagues.join(",")}:${jwt}
```

For the standard free bundle, `selectedLeagues = []`, so the message is:

```text
${txSig}::${jwt}
```

Send the detached wallet signature as base64 in `walletSignature`, and send the guest JWT from the matching network as `Authorization: Bearer <jwt>`.

## Epoch Day

An **epoch day** is the number of whole days since the Unix epoch, 1 January 1970 00:00 UTC. Compute it from a timestamp in milliseconds:

```typescript
const epochDay = Math.floor(timestampMs / 86_400_000); // 86,400,000 ms per day
```

Days are counted in UTC, so the epoch day changes at midnight UTC, not at local midnight. For example, 1 November 2026 15:20 UTC is `1793546400000` ms, which is epoch day `20758`.

The epoch day is used in two places:

- **On-chain root accounts.** Merkle roots are stored in one account per epoch day, and the epoch day is part of the account's PDA seeds. It is encoded as a u16, little-endian: 2 bytes, so day `20758` is the bytes `16 51`. A u16 holds days up to `65535`, which is in the year 2149.
- **API paths.** Endpoints such as `GET /api/scores/updates/{epochDay}/{hourOfDay}/{interval}` take the epoch day of the period you want. See [Fetching Snapshots](/documentation/examples/fetching-snapshots#time-period-parameters).

### Aligned Epoch Day

Fixture roots are stored ten days to an account. The account for a fixture proof is keyed by the **aligned epoch day**, the first day of its ten-day window: the epoch day rounded down to a multiple of 10.

```typescript
const alignedEpochDay = Math.floor(epochDay / 10) * 10; // day 20758 -> 20750
```

Day `20750` covers epoch days `20750` to `20759`, 24 October to 2 November 2026 UTC.

### Which Timestamp to Use

Derive the epoch day from the timestamp in the proof response, never from `Date.now()`. A proof can belong to an earlier day than today, for example a record from just before midnight UTC fetched just after it, so the current time can select the wrong account. Recompute it for every proof.

| Validation | Timestamp | Root account |
|------------|-----------|--------------|
| Scores (`validateStatV4`) | `payload.ts` from `GET /api/scores/stat-validation-v4` | `daily_scores_roots` for that epoch day |
| Odds (`validateOddsV4`) | `payload.ts` from `GET /api/odds/validation-v4` | `daily_batch_roots` for that epoch day |
| Fixtures (`validateFixture`) | `snapshot.Ts` from `GET /api/fixtures/validation` | `ten_daily_fixtures_roots` for the aligned epoch day |

## Public Validation Accounts

| Account | Seed(s) | Purpose |
|---------|---------|---------|
| Daily scores roots | `daily_scores_roots`, [epoch day](#epoch-day) as u16 little-endian | On-chain root account used for score proof validation |
| Daily batch roots | `daily_batch_roots`, [epoch day](#epoch-day) as u16 little-endian | On-chain root account used for odds proof validation |
| Ten daily fixtures roots | `ten_daily_fixtures_roots`, [aligned epoch day](#aligned-epoch-day) as u16 little-endian | On-chain root account used for fixture proof validation |

```typescript
import { PublicKey } from "@solana/web3.js";
import { BN } from "@coral-xyz/anchor";

const programId = new PublicKey("9ExbZjAapQww1vfcisDmrngPinHTEfpjYRWMunJgcKaA");

// For devnet, replace programId with:
// 6pW64gN1s2uqjHkn1unFeEjAwJkPGHoppGvS715wyP2J

function epochDayFromProofTimestamp(proofTimestampMs: number): number {
  if (!Number.isSafeInteger(proofTimestampMs) || proofTimestampMs < 0) {
    throw new Error("Expected a non-negative proof timestamp in milliseconds");
  }

  const epochDay = Math.floor(proofTimestampMs / 86400000);
  if (epochDay > 0xffff) {
    throw new Error("Proof timestamp is outside the u16 epoch-day range");
  }
  return epochDay;
}

function deriveDailyValidationPda(
  seed: "daily_scores_roots" | "daily_batch_roots",
  proofTimestampMs: number
): PublicKey {
  const epochDay = epochDayFromProofTimestamp(proofTimestampMs);
  return PublicKey.findProgramAddressSync(
    [Buffer.from(seed), new BN(epochDay).toArrayLike(Buffer, "le", 2)],
    programId
  )[0];
}

function deriveTenDailyFixturesPda(fixtureProofTimestampMs: number): PublicKey {
  const epochDay = epochDayFromProofTimestamp(fixtureProofTimestampMs);
  const alignedEpochDay = Math.floor(epochDay / 10) * 10;
  return PublicKey.findProgramAddressSync(
    [
      Buffer.from("ten_daily_fixtures_roots"),
      new BN(alignedEpochDay).toArrayLike(Buffer, "le", 2),
    ],
    programId
  )[0];
}
```

## Ticket Accounts

<Info>
On mainnet these accounts apply once mainnet runs the program version that includes `book_fixture`, `validate_fixture_for_tree`, and `close_worker_ticket`. Substitute the program ID of the network you use.
</Info>

| Account | Seed(s) | Used for |
|---------|---------|----------|
| Fixture ticket | `fixture_ticket`, wallet public key (32 bytes), `fixtureId` as u32 little-endian | Created by `book_fixture` per `(wallet, fixtureId)`; required by `validateStatV4` and `validateOddsV4` |
| Worker ticket | `worker_ticket`, wallet public key (32 bytes), `domain` as u8, `workerId` as u16 little-endian | Staged by `validateFixtureForTree`, consumed by `validateStatV4` / `validateOddsV4`, closed by `closeWorkerTicket` |
| Token treasury v2 | `token_treasury_v2` | Authority of the vault that receives TxL paid in `book_fixture`; the vault is its TOKEN-2022 associated token account for the TxL mint |

The IDL does not embed PDA seeds for these accounts, so the seeds above are not read from it. `fixtureId` is encoded as 4 bytes.

```typescript
function deriveFixtureTicketPda(wallet: PublicKey, fixtureId: number): PublicKey {
  return PublicKey.findProgramAddressSync(
    [Buffer.from("fixture_ticket"), wallet.toBuffer(), new BN(fixtureId).toArrayLike(Buffer, "le", 4)],
    programId
  )[0];
}

function deriveWorkerTicketPda(wallet: PublicKey, domain: number, workerId: number): PublicKey {
  return PublicKey.findProgramAddressSync(
    [
      Buffer.from("worker_ticket"),
      wallet.toBuffer(),
      Buffer.from([domain]),
      new BN(workerId).toArrayLike(Buffer, "le", 2),
    ],
    programId
  )[0];
}

const tokenTreasuryV2 = PublicKey.findProgramAddressSync([Buffer.from("token_treasury_v2")], programId)[0];
```

`domain` and `workerId` are client-chosen. See [On-Chain Validation](/documentation/examples/onchain-validation#v4-validation) for the sequence that uses them.
